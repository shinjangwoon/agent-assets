# 이슈 본문 형식

에이전트가 태스크(이슈)를 만들 때 따르는 본문 구조. 사람이 읽는 문서이자 DB(비고 등)로 그대로 흘러가는 원본이므로 정리된 형태여야 한다. 채팅 내용을 그대로 붙이지 않는다.

## 구조

```
(첨부 파일이 있으면 맨 위)

- 핵심 정보 목록 (기관 · 요청자 · 대상 시스템 · 요청 유형 등, 항목은 태스크 성격에 맞게)

---

## 1. 섹션 제목

- [ ] 체크리스트 항목
- [ ] …

## 2. 섹션 제목

| 표가 필요하면 표 |
```

## 규칙

- 첫 블록은 **핵심 정보 목록**. `- 키: 값` 형태. 읽는 사람이 3초 안에 무슨 건인지 알아야 한다.
- 구분선(`---`) 아래부터 본론. 작업 항목은 **체크리스트**로. 진행하면서 체크한다.
- 섹션이 여럿이면 번호를 붙인다(`## 1.`, `## 2.`). 순서가 의미 있을 때만.
- 확정 안 된 값은 `**(확정 필요)**` 로 표시한다. 추측으로 채우지 않는다.
- 하위 이슈는 본문 첫 줄에 `상위: <상위 이슈 제목>` 을 쓴다. 부모 링크가 없는 곳(DB 등)으로 갈 때도 관계가 남는다.

## 크기별

**단순 처리 (1시간 내)**
핵심 정보 목록 + 체크리스트 1개 섹션. 5줄 안팎.

**일반 작업**
핵심 정보 + 섹션 2~4개. 배경 · 작업 항목 · 검증.

**대형 (상위 이슈)**
핵심 정보 + 섹션 5개 이상. 하위 이슈 목록 섹션을 둔다. 표·첨부 활용.

## 예시

### 단순 처리

```
- 기관: A연구원
- 요청자: 담당자
- 대상 시스템: 접근제어 시스템
- 요청 유형: 계정 생성

---

## 요청 사항

- [ ] 유지보수 담당자 계정 생성 (계정명 **(확정 필요)**)
- [ ] DB 접근 권한 부여 — dev-db-01
- [ ] 생성 결과 요청자 회신
```

### 상위 이슈

```
- 대상: 컨테이너 플랫폼 클러스터
- 목적: 버전 EOS 대응 및 ingress 교체

---

## 1. 사전 준비

- [ ] 현행 구성 백업
- [ ] 영향 서비스 목록 정리

## 2. 하위 업무

- nginx ingress → haproxy ingress 마이그레이션
- (진행하며 파생되는 업무 추가)

## 3. 검증

- [ ] 서비스 정상 기동 확인
- [ ] 완료 보고
```

### 하위 이슈

```
상위: 플랫폼 업그레이드

- 대상: 플랫폼 ingress
- 범위: nginx ingress 제거, haproxy ingress 배포

---

## 작업 항목

- [ ] haproxy ingress 배포
- [ ] 라우팅 규칙 이관
- [ ] 전환 및 검증
- [ ] nginx ingress 제거
```
