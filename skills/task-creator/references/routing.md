# 분류 판단

## SR vs 내부 업무

**요청의 주체**로 판단한다.

| 주체 | 분류 | 예 |
|---|---|---|
| 고객 기관이 요청 | SR | "○○연에서 계정 만들어달래", "고객이 접속 안 된다고 함" |
| 우리가 해야 하는 일 | 내부 업무 | "구축 작업 정리", "자동화 개선", "문서 작성", "월간 보고 준비" |

애매하면 **한 번 묻는다**. "고객 요청입니까, 내부 작업입니까?"

## 단순 처리

SR 중 **접수 후 1시간 안에 끝나는 정형 작업**. 판단 기준은 작업 유형이지 난이도가 아니다.

- 계정 생성·삭제·권한 변경
- 방화벽/ACG 규칙 추가·삭제
- IP 차단·해제
- 단순 설정값 변경 (DNS 레코드, 포트 오픈)

아래는 단순 처리가 **아니다**.
- 원인 파악이 필요한 장애·오류 문의
- 증설·마이그레이션·구축
- 자료 작성·검토 요청

애매하면 붙이지 않는다. 단순 라벨은 있으면 좋고 없어도 무해하다.

## 상위 / 하위

아래 중 하나면 상위 1 + 하위 N 으로 나눈다.

- 요청에 독립적으로 완료 가능한 작업이 **2개 이상**
- "~하면서 파생되는", "~도 같이", "~단계로" 같은 표현
- 기간이 길고(2주 이상) 중간 산출물이 있음

하위는 상위의 **부모 연결**로 만들고, 하위 본문 첫 줄에 `상위: <상위 제목>`.

하위가 하나뿐이면 나누지 않는다. 그냥 본문 체크리스트로 둔다.

## 제목

`[약칭] 업무 주제` (기관이 있을 때). 15~30자.

- 접수 표현 제거: "요청", "확인 부탁", "문의드립니다", "관련"
- 동사형 → 명사형: "계정을 만들어주세요" → "계정 생성"
- 원본 제목에 기관명이 이미 들어 있으면 접두사와 중복시키지 않는다
